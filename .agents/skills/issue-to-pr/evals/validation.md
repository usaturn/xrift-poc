### REFACTOR（1 回）

GREEN の回答の末尾に、分かりにくかった点を書かせた。取りこぼしにつながるものだけを直した。

| 指摘 | 直したこと |
| --- | --- |
| 多数のテストが失敗したとき、位置に原因の行と失敗した対象のどちらを書くか | 原因の行をコードで確かめていなければ、失敗した対象のパスを書く |
| 「再実行で通す」が回避策の例にあるのに、最終化では再実行の成功を使ってよいとも読める | 回避策を「コマンド・環境変数・対象を変えて通すこと」とし、同じコマンドの再実行は回避策と分けた（失敗した実行は記録する） |
| PR の作成前に分かっていたのに PR 本文に書き漏れたものの補い方が無い | 記録のコメントで補い、判明した場面に書き漏れと書く |
| issue-to-pr の「停止時の報告」だけを読むと R1 で止まる | 停止条件に、回避策の条件を満たすものを除く旨と定義元への参照を足した |
