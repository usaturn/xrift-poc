# 長時間タスクの監視

完了（成果物または通知が届いた）、生存（対象プロセスがまだ存在する）、進捗（ログ出力が進んでいる）は別々のシグナルである。どれか 1 つから別のものを推測しない。

## 手順

1. `report exists OR worker is not alive` を待つ。レポートだけを待たない。この待機と stall のポーリングは controller が担当し、`report exists OR worker is not alive` が成立するまでターンを保持する。完了通知とは、ランタイムが出す終了コード付きのプロセス終了通知を指し、レポート・成果物・サブエージェントの結果は完了通知ではない。完了通知は `worker is not alive` の側を満たしうるが、worker が生存している間に controller のターンを終えてよいという許可ではない。待機にはランタイムの待機機能か通知機能を使い、フォアグラウンドの sleep ループは使わない。停止の例外は、期限または無進捗の打ち切りを過ぎた、事前宣言した読み取り専用の PR レビュー委譲だけである（「事前宣言した PR レビュー委譲の期限」の節を参照）。
2. 期待したレポートが無いままの終了は異常として扱う。対象の終了を観測した後にレポートを 1 回再確認し、その後は失敗として扱い、ログ末尾の `EXIT=<code>` を確認する。
3. 生存の確認には、既知の PID に対する `kill -0` を優先する。PID は対象を起動したときに控える（`verify-devenv.sh` はログのパスも PID も印字しない）。`verify-devenv.sh` が対象で `kill -0` が成功したら、その PID の同一性を確かめる。`ps -p <pid> -o args=` が `scripts/ci/verify-devenv.sh` を含み、かつ `readlink -f /proc/<pid>/cwd` が対象の worktree と一致すること。どちらかの同一性確認に失敗したら、対象の worker は生存していないものとして扱う。その PID について `pgrep` にフォールバックしない。それ以外の対象では、`kill -0` に加えて意図したコマンドラインと対象の cwd を確かめれば足りる。args に `scripts/ci/verify-devenv.sh` を含むことを求めない。`verify-devenv.sh` では、待機条件のどちらで待機が終わった場合も、起動時にログへ書き足した末尾の `EXIT=<code>`（またはランタイムが返す終了コード）を確認する。
4. `pgrep -f` は PID が得られないときだけ使う。対象のコマンドラインに一致させ、パターンの文字列自体が一致しないように、パターンをスクリプトファイルに置くか、`[s]cripts/ci/verify-devenv\.sh` のようなパス付きのブラケット形式を使う。ただし、監視コマンドの別の箇所に対象のパスをそのまま書くと、それが監視コマンド自身に一致することがある。一致した結果を確かめ、監視プロセスの PID とその祖先のすべての PID を除く。対象が `verify-devenv.sh` のときは、残った各 PID に手順 3 の `verify-devenv.sh` 用のコマンドライン・cwd の同一性確認を適用する。対象が `verify-devenv.sh` でないときは、コマンドラインが意図した対象のコマンドに一致し、かつ cwd が対象の worktree である PID を残す。1 つも残らなければ、対象の worker は生存していない。ログのパスをプロセスの目印に使わない。
5. `verify-devenv.sh` は起動する側がログの出力先を決める（例: `tmp/agents/<topic>.XXXXXX/` の下）。そのパスを控えて監視する。
6. 約 10 分ごとに、ログの mtime、サイズ、または最終行を確認する。2 回続けて変化が無ければ stall として報告する。生存中で stall したタスクがあっても、それを kill してよい許可には決してならない。例外は、「事前宣言した PR レビュー委譲の期限」の節で扱う、事前宣言した読み取り専用の PR レビュー委譲だけである。
7. 依存する作業を起動する前に報告する。状況報告には毎回、タスクの識別情報、実際のログのパス、終了コード（判明しているか不明か）、最後の進捗を含める。

## 事前宣言した PR レビュー委譲の期限

これは、生存中の worker を停止しないというルールに対する、範囲を絞った事前宣言の例外である。対象は、委譲対象の識別情報・絶対期限・無進捗の打ち切り・キャンセルの手段を起動前に記録した、読み取り専用の PR レビュー委譲だけである。親は委譲の期限を「起動時刻 + 10 分」とレビューの調査期限のうち早いほうに設定し、その期限に達した時点、または実質的な進捗が無いまま 5 分たった時点で worker を停止する。進捗が実質的かどうかは time-budget の参照文書に従う。heartbeat、同じ状態の繰り返し、ログの mtime だけの更新では、無進捗の時計をリセットしない。

- worker は期限で停止する。進捗を理由に期限を延ばさず、worker を再び起動しない。
- 停止を 1 回確認する（試行は 1 回程度、上限は 30 秒前後）。キャンセルを確認できない場合は、委譲対象、停止を確認できていない状態、委譲対象がまだ使う可能性のあるすべてのパスを報告してから、ターンを終える。依存する作業を開始せず、委譲対象の worktree を削除しない。
- この例外は検証コマンドや実装 worker には適用せず、一般のタスクを停止するために流用してはならない。生存・進捗・完了は引き続き別々のシグナルであり、PID の同一性確認もそのまま適用する。

## 早見表

| 状態 | 対応 |
| --- | --- |
| `completed` | レポートが届いた。レポートを読み取って先へ進む。 |
| `exited without report` | 異常。レポートを再確認し、失敗を報告し、`EXIT=<code>` を確認する。 |
| `alive and progressing` | 待機を続ける。最新のログ位置を記録する。 |
| `alive but stalled` | 4 項目すべてを付けて stall を報告する。タスクは停止せずに残し、依存する作業を保留する。 |
| `predeclared PR review delegation past deadline` | 期限または無進捗の打ち切りで停止する。停止を 1 回確認する。停止を確認できなければ報告し、依存する作業を始めずにターンを終える。 |

## よくある誤り

| 誤り | 直し方 |
| --- | --- |
| レポートの存在だけを待つ | `report exists OR worker is not alive` を待つ。 |
| 監視プロセスに一致してしまうインラインの `pgrep -f` | スクリプトファイルかブラケット形式のパターンを使い、一致した結果を確かめる。 |
| ログのパスを `pgrep` の目印に使う | コマンドラインに一致させる。ログのパスは進捗の確認だけに使う。 |
| 固定先への手動のログリダイレクトを必須にする | 実行ごとに印字されたログのパスを使う。 |
| 期限に間に合わせるために、生存中で stall したタスクを kill する | stall を報告して判断を求める。ただし、期限または無進捗の打ち切りを過ぎた、事前宣言した読み取り専用の PR レビュー委譲は除く（「事前宣言した PR レビュー委譲の期限」の節を参照）。 |
| 事前宣言の例外に当たらない生存中の worker を停止する | 停止してよいのは事前宣言した読み取り専用の PR レビュー委譲だけであり、それも期限または無進捗の打ち切りのときだけである。 |
| 報告する前に依存する作業を始める | 先に報告し、状況の 4 項目をすべて含める。 |

結果をそのまま返す短い同期コマンドには、このスキルを使わない。
